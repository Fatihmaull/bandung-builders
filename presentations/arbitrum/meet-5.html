Block A · 40 min

The math flow — from rewardRate to a user's APR

Pop quiz: if rewardRate = 1e16 (i.e. 0.01 reward tokens per second) and totalStaked = 1,000 tokens, what is a user's APR assuming the reward token and the staking token have the same dollar price?

Work it out:

  • Per second: each staked token earns 0.01 / 1,000 = 1e-5 reward tokens.
  • Per year (31,536,000 s): each staked token earns 315.36 reward tokens.
  • APR = 315.36 / 1 = 31,536%.

That's clearly nonsense for a real protocol — emissions of that scale would dilute holders into oblivion. This is exactly the calculation founders skip and then their token launches at $1 and trades at $0.01 by week 2.

The general formula:

APR formula
APR = (rewardRate × secondsPerYear × P_reward)
    / (totalStaked × P_staking)

Block B · 40 min

Emission schedules & runway

Constant rewardRate looks neat in code; it is rarely the right economic shape. Three common families:

  • Flat — same emission per second forever. Easy to model. Cheap to game.
  • Linear-decay — emission decreases linearly to 0 over T. Bootstraps early stakers, fades politely.
  • Halving — like Bitcoin. Drops by 50% every T. Hard cap, strong "scarcity" narrative.

The MVP uses flat. You should be able to articulate when you'd switch.

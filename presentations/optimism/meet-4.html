Solidity Fast-Track · 20 min

Solidity Fast-Track Prep

Sebelum memulai proyek staking DeFi yang kompleks, mari segarkan ingatan tentang sintaks dasar dan konsep penting Solidity:

1. Struktur Dasar

Setiap file Solidity (.sol) wajib memiliki lisensi SPDX dan versi kompiler pragma.

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract BelajarSolidity {
    string public teks; // State Variable (disimpan di blockchain)

    // Fungsi mengubah data (Menulis -> Membutuhkan Gas)
    function setTeks(string memory _teksBaru) public {
        teks = _teksBaru;
    }

    // Fungsi membaca data (Membaca -> view/pure gratis untuk pemanggilan eksternal)
    function getTeks() public view returns (string memory) {
        return teks;
    }
}

3. Tipe Data Kunci

  • uint256: Bilangan bulat tak bertanda 256-bit (digunakan untuk saldo token dan timestamp).
  • address: Menyimpan alamat dompet atau alamat smart contract lain.
  • mapping(key => value): Struktur data hash-map yang efisien secara gas untuk memetakan alamat user ke saldo mereka.

3. Visibility & Mutability

  • Visibility: public (siapa saja), external (hanya luar), internal (kontrak & turunan), private (hanya internal kontrak).
  • Mutability: view (hanya membaca state), pure (tidak membaca/menulis state).
Frame · 10 min

The mental model

Imagine a tap dripping reward tokens into a pool at rewardRate tokens per second. Everyone with stake in the pool owns a share of the drip proportional to their stake. Naive implementation: iterate over every staker on every second to credit their share. That is O(n) and would gas-implode the chain.

The Synthetix accumulator solves this with a single global counter — rewardPerTokenStored — measured in "reward-tokens per staked-token, scaled by 1e18". Whenever anyone interacts, two things happen:

  1. Advance the global counter by elapsed-time × rate / totalStaked.
  2. Snapshot the current counter for that one user (userRewardPerTokenPaid).

Now earned(user) = balanceOf(user) × (current − userSnapshot). O(1) per interaction. Beautiful.

Math we encode
rewardPerToken() = rewardPerTokenStored
                 + (now − lastUpdateTime) × rewardRate × 1e18 / totalStaked

earned(user)     = balanceOf[user] × (rewardPerToken() − userRewardPerTokenPaid[user]) / 1e18
                 + rewards[user]

Read the interface together

Open IStakingProtocol.sol on the projector. The interface is the contract you owe the world.

interface IStakingProtocol {
    // ---- events ----
    event Staked(address indexed user, uint256 amount);
    event Withdrawn(address indexed user, uint256 amount);
    event RewardPaid(address indexed user, uint256 amount);
    event RewardRateUpdated(uint256 newRate);
    event RewardsFunded(address indexed funder, uint256 amount);

    // ---- custom errors ----
    error ZeroAmount();
    error InsufficientBalance();
    error InsufficientRewardLiquidity();

    // ---- views ----
    function rewardPerToken() external view returns (uint256);
    function earned(address account) external view returns (uint256);

    // ---- user actions ----
    function stake(uint256 amount) external;
    function withdraw(uint256 amount) external;
    function getReward() external;
    function exit() external;

    // ---- admin ----
    function setRewardRate(uint256 newRate) external;
}

Block B · 30 min

State variables & the updateReward modifier

State layout (writing live)

contract StakingProtocol is IStakingProtocol, ReentrancyGuard, Ownable {
    using SafeERC20 for IERC20;

    uint256 private constant PRECISION = 1e18;

    IERC20 public immutable stakingToken;
    IERC20 public immutable rewardToken;

    uint256 public rewardRate;          // tokens per second, scaled in token units
    uint256 public lastUpdateTime;
    uint256 public rewardPerTokenStored;

    mapping(address => uint256) public userRewardPerTokenPaid;
    mapping(address => uint256) public rewards;

    uint256 public totalStaked;
    mapping(address => uint256) public balanceOf;
}

The modifier — write it first, then explain

modifier updateReward(address account) {
    rewardPerTokenStored = rewardPerToken();
    lastUpdateTime = block.timestamp;

    if (account != address(0)) {
        rewards[account] = earned(account);
        userRewardPerTokenPaid[account] = rewardPerTokenStored;
    }
    _;
}
Defend the order

Settle BEFORE the state change. If a user stakes before we update, their new bigger balance back-dates over time they didn't actually have it. If a user withdraws after we update, they lose accrual they earned.

The views

function rewardPerToken() public view returns (uint256) {
    if (totalStaked == 0) {
        return rewardPerTokenStored;
    }
    uint256 elapsed = block.timestamp - lastUpdateTime;
    return rewardPerTokenStored + (elapsed * rewardRate * PRECISION) / totalStaked;
}

function earned(address account) public view returns (uint256) {
    uint256 delta = rewardPerToken() - userRewardPerTokenPaid[account];
    return (balanceOf[account] * delta) / PRECISION + rewards[account];
}

Block C · 40 min

User actions: stake, withdraw, getReward

The exercise file ships with these as // TODO blocks. We type the reference implementation together. Click the toggles to reveal the canonical version when you're ready to compare.

stake()

function stake(uint256 amount) external nonReentrant updateReward(msg.sender) {
    if (amount == 0) revert ZeroAmount();

    totalStaked += amount;
    balanceOf[msg.sender] += amount;

    stakingToken.safeTransferFrom(msg.sender, address(this), amount);
    emit Staked(msg.sender, amount);
}
CEI (Checks-Effects-Interactions)

All accounting (Effects) is done before the external call (Interaction). Combined with nonReentrant this is belt-and-suspenders against reentrancy on stake.

withdraw()

function withdraw(uint256 amount) public nonReentrant updateReward(msg.sender) {
    if (amount == 0) revert ZeroAmount();
    if (balanceOf[msg.sender] < amount) revert InsufficientBalance();

    totalStaked -= amount;
    balanceOf[msg.sender] -= amount;

    stakingToken.safeTransfer(msg.sender, amount);
    emit Withdrawn(msg.sender, amount);
}

getReward()

function getReward() public nonReentrant updateReward(msg.sender) {
    uint256 reward = rewards[msg.sender];
    if (reward == 0) return;

    if (rewardToken.balanceOf(address(this)) < reward) {
        revert InsufficientRewardLiquidity();
    }

    rewards[msg.sender] = 0;
    rewardToken.safeTransfer(msg.sender, reward);
    emit RewardPaid(msg.sender, reward);
}

Why nonReentrant? — the attack visualised

  1. Attacker stakes X.
  2. Attacker waits to accrue rewards.
  3. Attacker calls getReward() from a malicious ERC20 reward token (or a malicious receiver).
  4. The malicious token's transfer() hook calls back into getReward() before rewards[attacker] = 0.
  5. Without nonReentrant: attacker drains rewards repeatedly.
  6. With nonReentrant: re-entry reverts immediately with ReentrancyGuardReentrantCall.

Why not only CEI? Because reward token is configurable — a future malicious or upgradeable reward token could violate our assumptions. The guard is defense-in-depth.

exit() — convenience

function exit() external {
    uint256 staked = balanceOf[msg.sender];
    if (staked > 0) {
        withdraw(staked);
    }
    getReward();
}

Owner: setRewardRate & fundRewards

function setRewardRate(uint256 newRate) external onlyOwner updateReward(address(0)) {
    rewardRate = newRate;
    emit RewardRateUpdated(newRate);
}

function fundRewards(uint256 amount) external onlyOwner {
    if (amount == 0) revert ZeroAmount();
    rewardToken.safeTransferFrom(msg.sender, address(this), amount);
    emit RewardsFunded(msg.sender, amount);
}
Critical: pass address(0) on rate-change

We're not interacting with any specific user — we just want to settle the global accumulator at the OLD rate before flipping it. Forgetting this is the most common audit finding in homegrown forks of this pattern.

Block D · 30 min

Forge tests with vm.prank + vm.warp

Open contracts/test/StakingProtocol.t.sol. Walk through each test.

Sample: time-based reward accrual

function test_RewardAccrualOverTime() public {
    // Alice and Bob stake 100 each
    vm.prank(alice);
    staking.stake(100e18);
    vm.prank(bob);
    staking.stake(100e18);

    // Fast-forward 1 hour
    vm.warp(block.timestamp + 1 hours);

    // Expected: rewardRate × 3600 split evenly
    uint256 expected = REWARD_RATE * 3600 / 2;
    assertApproxEqAbs(staking.earned(alice), expected, 1e9);
    assertApproxEqAbs(staking.earned(bob),   expected, 1e9);
}

Sample: reentrancy guard

function test_RevertsWhen_ReentrantClaim() public {
    // ReentrantToken's transfer() hook tries to call getReward() again.
    vm.prank(attacker);
    vm.expectRevert(); // ReentrancyGuardReentrantCall
    staking.getReward();
}

Common gotchas
  • Division before multiplication — (elapsed * rewardRate * PRECISION) / totalStaked, not the other order. Otherwise you truncate to zero.
  • Forgot updateReward on setRewardRate — historical accrual leaks at the new rate. Audit finding.
  • Reentrancy on reward token — only an issue if the reward token has hooks. We assume it doesn't, but nonReentrant protects us anyway.

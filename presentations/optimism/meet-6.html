Block A · 40 min

Providers (order matters)

// frontend/src/app/providers.tsx
"use client";

import "@rainbow-me/rainbowkit/styles.css";

import { ReactNode, useState } from "react";
import { WagmiProvider } from "wagmi";
import { RainbowKitProvider } from "@rainbow-me/rainbowkit";
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";

import { wagmiConfig } from "@/lib/wagmi";

export function Providers({ children }: { children: ReactNode }) {
  const [queryClient] = useState(() => new QueryClient());

  return (
    <WagmiProvider config={wagmiConfig}>
      <QueryClientProvider client={queryClient}>
        <RainbowKitProvider>{children}</RainbowKitProvider>
      </QueryClientProvider>
    </WagmiProvider>
  );
}
Order matters

Wagmi → TanStack Query → RainbowKit. RainbowKit depends on Query (for tx cache), which depends on Wagmi (for config). Invert the order and you get cryptic "QueryClient not found" errors at runtime.

Pinned to optimismSepolia

We pass a one-element array. That guarantees the user cannot accidentally try to use mainnet. RainbowKit will offer a "switch network" prompt if their wallet is on anything else.

Block B · 30 min

Read hooks: useEarnedRewards

// frontend/src/hooks/useEarnedRewards.ts
import { useAccount, useReadContract } from "wagmi";
import { STAKING_CONTRACT_ADDRESS, stakingAbi } from "@/lib/contracts";

export function useEarnedRewards() {
  const { address } = useAccount();

  return useReadContract({
    address: STAKING_CONTRACT_ADDRESS,
    abi: stakingAbi,
    functionName: "earned",
    args: address ? [address] : undefined,
    query: { enabled: Boolean(address), refetchInterval: 6_000 },
  });
}

What just happened, line by line

  • useAccount pulls the connected wallet from Wagmi's React context.
  • Reads disabled before connect via query.enabled. Don't fire RPC calls into the void.
  • refetchInterval — poll every 6 s. Reward accrues in time; polling makes "earned" tick up on screen.
  • Return value is the standard TanStack { data, isLoading, isError, error, refetch }.
BigInt rendering

data is a bigint for uint256 returns. Format with formatUnits(data, 18) from viem before showing the user. React will throw if you render a bare bigint.

Block C · 30 min

Write hooks & the transaction lifecycle

// frontend/src/hooks/useStakeTokens.ts
import { useCallback } from "react";
import { useWriteContract, useWaitForTransactionReceipt } from "wagmi";
import { STAKING_CONTRACT_ADDRESS, stakingAbi } from "@/lib/contracts";

export function useStakeTokens() {
  const {
    writeContract, data: hash,
    isPending, error: writeError, reset,
  } = useWriteContract();

  const {
    isLoading: isConfirming, isSuccess: isConfirmed,
    error: receiptError,
  } = useWaitForTransactionReceipt({ hash });

  const stake = useCallback((amount: bigint) => {
    writeContract({
      address: STAKING_CONTRACT_ADDRESS,
      abi: stakingAbi,
      functionName: "stake",
      args: [amount],
    });
  }, [writeContract]);

  return {
    stake, hash,
    isPending, isConfirming, isConfirmed,
    error: writeError ?? receiptError, reset,
  };
}

Interactive · The transaction lifecycle in real time

Click "Submit". Watch the states transition. This is exactly what the user sees in their UI when they click "Stake" — every step has a name; every state needs UI.

idle
isPending — wallet open
isConfirming — in mempool
isConfirmed ✓
click to start
UI implication

You need four UI states minimum: a default button, a disabled-with-spinner button ("Waiting for wallet…"), a disabled-with-spinner ("Confirming on OP Sepolia…"), and a success state. Plus an error toast that doesn't dismiss too quickly.

Exercise · 20 min

useApproveStake — your turn

Every stake() transaction will revert with ERC20InsufficientAllowance unless the user has first approved the staking contract to pull their tokens. That's a separate transaction. Today you implement the hook for it.

Use useStakeTokens.ts as the model. Differences:

  • The contract you write to is the staking token, not StakingProtocol.
  • The function is approve(spender, amount) with spender = STAKING_CONTRACT_ADDRESS.
  • You'll need useReadContract to check current allowance before showing the approve button.

  const { data: allowance, refetch: refetchAllowance } = useReadContract({
    address: STAKING_TOKEN_ADDRESS,             // TODO 1

    args: address ? [address, STAKING_CONTRACT_ADDRESS] : undefined,
    query: { enabled: Boolean(address) },

      address: STAKING_TOKEN_ADDRESS,           // TODO 3
      abi: erc20Abi,
      functionName: "approve",
      args: [STAKING_CONTRACT_ADDRESS, amount], // TODO 4
    });
  }, [writeContract]);

  useEffect(() => {                             // TODO 5

  }, [isConfirmed, refetchAllowance]);

    hash, isPending, isConfirming, isConfirmed,

Why maxUint256 as default?

UX: one approve covers the entire user lifetime. Without it, every stake = two transactions. Trade-off: a buggy contract can drain the entire balance. For this protocol — audited test code, no admin-set token — the UX win is worth it.

Gotchas you will hit
  • Reading before connect — guard with query.enabled.
  • BigInt math in JSX — never {amount + fee} on bigints inside JSX without .toString().
  • Stale allowance after approve — must refetchAllowance() on isConfirmed, otherwise the stake button stays disabled.
  • Network mismatch — RainbowKit prompts; trust it.

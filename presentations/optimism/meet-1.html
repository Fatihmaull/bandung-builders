Block A · 35 min

Ethereum & the EVM as a deterministic state machine

Forget cryptocurrency for a moment. The Ethereum Virtual Machine is one thing: a global, deterministic state machine. Given the same starting state and the same input, every node on Earth must compute the same next state. That is the entire trick.

Interactive · The state machine, one transaction at a time
STATE @ block N
Alice: 100 ETH
Bob: 50 ETH
Counter: 0
→
STATE @ block N+1
Alice: 100 ETH
Bob: 50 ETH
Counter: 0

Determinism check: click any button. The "after" state is a pure function of the "before" state plus the transaction. No clock, no randomness, no network. Same input → same output, on every node.

EVM anatomy in 6 bullets

1. Accounts

EOAs are key-controlled. Contracts are code-controlled. Both have a wei balance. Contracts also have persistent storage.

2. State

Global key-value: address → {balance, nonce, codeHash, storageRoot}. Committed by a Merkle-Patricia trie.

3. Transactions

A signed message from an EOA: "from addr, pay gasPrice, do calldata against to".

4. Gas

Every opcode has a fixed cost. Gas bounds compute per transaction so the network cannot be DoS'd by infinite loops.

5. Opcodes

~150 opcodes. ADD, SSTORE, CALL, KECCAK256. Solidity compiles to these.

6. Storage vs Memory vs Calldata

Storage is persistent & expensive. Memory is RAM-like, dies after the call. Calldata is read-only input, cheapest.

Repeat after the facilitator

"Solidity is a thin language wrapped around opcodes. Every line you write maps to gas."

Determinism + gas → why we need scaling

Because every node on Earth has to execute every transaction, you cannot just throw more compute at Ethereum. Adding a faster machine doesn't help — every other node still has to follow along. So Ethereum scaled to the L1's natural limit: ~15 tx/s, $2–$50 per swap during demand spikes.

That is unshippable for a consumer dApp. The solution is rollups. OP Sepolia is our workshop deployment target.

Block B · 40 min

Why L2? Rollup mechanics & OP Stack

A rollup does two things. First, it executes transactions off the main chain — at its own pace, with its own cheap fees. Second — and crucially — it posts a compressed summary back to Ethereum L1. The L1 contract is the truth source. The rollup borrows L1's security.

flowchart LR users["L2 Users"] -->|"transactions"| seq["L2 Sequencer (OP Stack)"] seq -->|"execute"| l2exec["Cheap, fast L2 execution"] l2exec -->|"state root"| l1["L1 Rollup Contract on Ethereum"] l1 -.->|"borrows security"| l2exec

Two flavors of rollup:

  • Optimistic (Optimism, Base, Arbitrum) — assume the sequencer is honest, allow disputes via a fraud proof during a ~7-day window.
  • Zero-knowledge (zkSync, Scroll, Linea) — post a cryptographic proof of correctness; faster finality, more expensive to prove.

OP Sepolia is an optimistic OP Stack chain. The 7-day window only affects withdrawal-to-L1; intra-L2 activity is instant.

The OP Stack & why we deploy on OP Sepolia

OP Sepolia is the testnet for Optimism's OP Stack — the same rollup framework that powers Base, Mode, Zora, and other Superchain members. We deploy here directly on the parent stack rather than a branded instance.

Why does that matter to you? Three things:

  1. EVM-equivalence. Bytecode-identical to Ethereum L1. Same Solidity, same opcodes, same Foundry/Wagmi tooling.
  2. Superchain interoperability. Skills transfer to Base, Mode, and other OP Stack chains with config changes only.
  3. Accessible faucet. The Superchain Faucet (console.optimism.io/faucet) uses GitHub login — no mainnet ETH required.

Superchain deep dive — why Optimism, not just "another L2"

Optimism maintains the OP Stack — open-source software for launching optimistic rollups. Chains that adopt it form the Superchain: a network of L2s that share upgrades, security research, and (over time) interoperability standards.

OP Sepolia vs Base Sepolia

Both are OP Stack chains with identical EVM bytecode. Base is Coinbase's branded deployment with distribution moat. OP Sepolia is the reference testnet for the stack itself — best for learning how rollups work before picking a brand.

Fault proofs & the 7-day window

Optimistic rollups assume batches are valid unless challenged. A fault proof on L1 can revert a bad batch. Withdrawals to L1 wait for this window; deposits and L2 txs do not. Your staking dApp users never feel the 7-day delay unless they bridge out to L1.

The Bandung vision & the cohort contract

Bandung punches above its weight in software. The university density (ITB, UNPAD, TELU), the agency ecosystem, the cost of living — every ingredient of a great builders' city. What it does not yet have on the global stage is a critical mass of Web3 protocol talent.

The thesis behind this cohort: Web3 doesn't get built where capital is. It gets built where talent is. The capital flies to the talent. Lens, Aave, dYdX — none originated in Silicon Valley. The Bandung answer is to make this room one of the densest concentrations of L2-native builders in Southeast Asia.

The cohort contract

Rules of the Game

Builder cohorts succeed or fail based on habits, not talent. These five rules are non-negotiable. Read, sign, hand in.

1. Ship over polish (until Week 4)

Weeks 1–3: imperfect & merged beats perfect & local. We polish in Week 4.

2. Every PR is reviewed by one peer

No solo merges to main. Reviewer runs forge test or pnpm dev and leaves a substantive comment.

3. Every contract change ships with a test

A forge test change must accompany every Solidity diff that touches behavior. A contract without tests is a hypothesis, not a deliverable.

4. No mainnet anything

OP Sepolia only. No mainnet RPC URLs. No mainnet private keys. The .cursorrules is configured to refuse mainnet suggestions.

5. AI is a co-pilot, not the pilot

You must be able to explain every line you commit. In peer review, "the AI wrote it" is not an answer.

AI usage policy summary
  • ✅ Allowed: AI generates scaffolding, tests, boilerplate. AI explains a diff or concept. AI suggests refactors.
  • ❌ Forbidden: AI does your peer review. Copy-pasting AI output you cannot defend. AI-generated pitch claims without verification.
